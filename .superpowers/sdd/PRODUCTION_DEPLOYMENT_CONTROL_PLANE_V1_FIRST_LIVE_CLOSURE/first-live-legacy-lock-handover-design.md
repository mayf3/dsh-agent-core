# Exact legacy lock handover clarification

Same parent/accepted3986553, REUSE, controlled nonproduction implementation only. This clarifies the design's existing requirement to serialize before target effects. Absence alone is not a lock acquisition: a legacy entrant can acquire its mkdir lock after census and before executable retirement. The fixed native operator must close that concrete interval, without a lock-inheritance channel or stale-lock cleanup.

Source evidence is pinned in legacy-lock-source-bindings.json. The installed/source trusted installer and authorized Watchdog wrapper acquire `/usr/local/var/agent-core/production-mutation-locks/production-deploy.lock` using exclusive mkdir, then write a holder with pid/uid/cmd/started. The retained Scheduler freeze exclusively mkdir0700 at `/var/db/agent-core/production-transaction.lock`, then records its own freeze-receipt. The retained session-trace root transaction opens `/var/run/agent-core-production-mutation.lock` as a root regular0600 and takes nonblocking flock; its permanent inode must remain. `/var/db/agent-core/deployments/transaction.lock` is an additional existence-based conflict guard in the located active wrappers, not a verified independently reusable writer protocol. No current privileged lock observation is claimed.

## Selected finite transition

Under the unchanged permanent DCP production.lock, acquire the retained session-trace regular flock without replacement or inherited-FD strings. Its exact expected absence/existence and inode are packet preconditions; creating an absent permanent0600 lock is permitted only when expressly bound by the final operation, using O_EXCL and durable creation intent, then retaining that inode forever. Never chmod an unexpected existing lock to make it pass.

Acquire the two known ephemeral directory locks in one deterministic fixed order, using protected parent descriptors and atomic mkdirat (0700). Before mkdir, persist a DCP operation intent with exact parent/preimage and step; after success verify and retain the actual directory device/inode. Create an exclusive root0600 holder naming this exact DCP operation, its executable/process identity and package. For production-deploy.lock, also preserve the readable historical pid/uid/cmd/started lines, adding the operation/package binding; it must never match an old parent-inheritance pattern. For production-transaction.lock, use a distinct dcp-handover.json, not a forged Scheduler freeze receipt. Existing object of any kind, failed mkdir or unexpected parent/contents aborts without unlinking it. Acquisition never borrows or changes someone else's holder.

The deployments/transaction.lock guard must be absent before and after acquisition and remain absent through the target-effect preflight. The fixed known legacy writer census must prove every canonical active path either honors one acquired protocol or is already refused by the retired native executable. An unclassified writer or unknown lock protocol is a stop, not permission to label this guard acquired. No invented fourth mutex format or blind lock conversion is permitted.

Retain all acquired locks through executable retirement, service/metadata changes, genuine proof and final controlled readback. Release regular flocks only by closing descriptors; never unlink permanent files. After the successful journaled handover and verified retired old entries, remove only this operation's exact owned ephemeral holder(s), compare directory inode and exact content set, then rmdir its own empty directory while DCP mutex remains held. This is normal release of newly acquired ephemeral locks, never stale/foreign lock deletion. A crash, partial effect, unknown holder/result or changed directory keeps locks/evidence in place and requires same-operation reconciliation; do not issue another attempt ID or apply a PID-age heuristic.

Fixtures must demonstrate real mkdir exclusion against a competing legacy acquisition, regular flock exclusion with same inode retained, deterministic partial-acquisition stop, crash between intent/mkdir/holder/result, foreign preexisting directories unchanged, changed/replaced holders never removed, and only fully owned empty directories released after retirement completion. Native owner authorization and installed readback remain separately required; no real lock operation is performed during development.
