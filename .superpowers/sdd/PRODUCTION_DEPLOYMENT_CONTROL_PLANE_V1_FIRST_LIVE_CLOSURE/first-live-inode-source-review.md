## Construction, old capabilities and archive durability

Source files are opened through protected retained directory descriptors with bounded literal path parsing and no following of symlinks. Each old regular descriptor must match the expected device/inode, closed link count, owner/group/mode and zero flags, reject ACL/unknown xattrs, and yield bytes matching the frozen SHA. The bounded read also requires stable size, ctime, mtime and allowed xattrs while reading. A changed old handle cannot inject different bytes into the archive because the collected bytes must match the expected digest. Full packet/preflight metadata binding and complete inventory remain external obligations described below.

The archive is a separately allocated exclusive regular file, owned by the trusted root/fixture owner and mode0400. Existing write_new synchronizes its bytes/metadata and directory; restore_times separately synchronizes allowed xattrs and timestamps. The archive is read back before any target replacement. It is neither a link nor rename of the old inode. New final files are independently allocated again, receive the approved owner/group/mode and preserved allowed xattrs/time, are synchronized, and are read back before the immutable per-group target intent is published. Target parent directories are fsynced after each rename.

Therefore an old writable FD or writable MAP_SHARED mapping refers only to the detached predecessor after publication. It has no capability to mutate the archive or trusted final inode. Root0644/0755 are valid trusted-owner modes; the new mask excludes group/other write and set-id/sticky bits. This preserves the existing profile's root-owner semantics rather than incorrectly treating root write as caller write.

## Closed pairs and partial publication

The component groups regular files by exact original device/inode. Each group contains one or two names only, each member has identical expected metadata and its observed link count must equal the complete group. The first new final file is hardlinked only to the second private staging name for a pair; the resulting inode is different from the predecessor and has exactly the expected count. Both target names are bound in a single durable intent. Each publication rechecks the remaining old names and declining old link count. Final readback requires both paths to reach the exact new shared inode and frozen bytes, with no extra alias.

A crash can expose one new and one old path. It cannot create a successful group result. Reentry rejects the consumed intent or prior exclusive archive/staging file instead of restarting silently. Complete proof that only the three frozen harness pairs exist belongs to the prior full inventory validation; this private generic-per-tree component permits a two-name group but does not itself establish the global approved pair set.

## Recovery and unknown disposition

Recovery reads the protected exact original intent, verifies its paths/preimage/postimage relation and independently snapshots the newly sealed archive. It refuses changed/corrupt archive bytes/metadata, wrong current inode, wrong hash/metadata or expired authorization. Current paths must be exactly the recorded predecessor or new postimage, and any still-staged names must point to the recorded new inode with the correct closed count. Recovery constructs another new inode from the sealed bytes; it does not reconnect old detached writable-capability inodes.

A separate exclusive restore intent precedes recovery publication. The current path is checked again immediately before each rename. Cleanup removes only precisely recorded leftover staging names, with current identity/hash/count checks and parent sync. Final readback precedes the immutable restore result. A consumed recovery intent is never replayed. The six tested interruption points cover archive-only, durable target intent, each pair publication, and before/after recovery publication.

This is **bounded guarded recovery**, not guaranteed automatic recovery from every unknown. A crash before durable target intent retains the archive but refuses recovery; a missing group record or interrupted restore likewise stops without manufacturing completion. For a partly processed multi-group tree, earlier groups may already have been restored when a later missing/unknown record is encountered; the caller must retain that failed/partial disposition and require exact reconciliation. Restoration of approved original metadata can restore old service-account ownership; it provides availability recovery only, while admission remains disabled. It must never be mistaken for a successful protected adoption or standing activation. Retired writer restoration remains separately prohibited by the operation's exact write set and recovery plan.
