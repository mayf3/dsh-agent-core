## Complete bounded blocker union

**LH-01 — a path/name-only known-interpreter census misses an inherited root writer.** Concrete counterexample: old Node starts native child X and exits; X is reparented and remains root. Neither “no Node/bash” nor current PPID matching detects X. Another counterexample is skipping an ESRCH row during a scan: it may have forked a surviving child after PID enumeration and then exited. Do not label such incompleteness clean. A fixed list of copied legacy source names is not a complete executable closure for the actual installed bridge.

**LH-02 — proposed exact exceptions and ingress ordering are not yet frozen.** Current unrelated root processes include non-SSV/third-party and transient roles. Whitelisting all baseline PIDs, all Apple executable paths, all root-owned files, or all children of launchd would silently accept an unproven writer. The exact accepted classification must exist before the source claims complete census. In particular a protected Apple utility such as `install`, `cp`, a shell, Python or launchctl is not necessarily a trusted daemon; the old bridge itself can invoke those utilities. Ordinary process-path observations alone cannot establish the role or provenance of third-party daemons. If the finite classification cannot prove a row, stop before protected-face isolation/publication rather than adding it automatically.

These are one directly affected handover issue and its concrete classification/ordering closure, not reopened unrelated findings or a request for a general host security platform.

## Minimal defensible operational design

1. Retain the exact controller mutex and actual legacy locks; publish the pending fence. Before mutation, perform a conservative current census and refuse visible unclassified in-flight writers. **Close the actual NOPASSWD bridge as the first relevant retirement effect**, with exact preimage and protected native refusal readback. A newly installed marker cannot be assumed to constrain an already-invoked old body or an installed body without that check. Other known canonical ingress must be locked or retired before the decisive absence census. There must be no omitted direct privilege path or non-honoring writer.
2. After ingress closure and before any code/loader isolation, enumerate all processes with a bounded kernel PID list, not just selected interpreter names. Resolve each root row using complete kernel executable path, real/effective identity as applicable, PPID and precise birth identity; validate the same identity/path again after classification. Treat full buffers, malformed/duplicate rows, inaccessible identity/path, unexpected credential/path change and disappearing rows as unknown. A vanished row cannot be silently ignored. Keep a bounded fresh second census and require the accepted generation set to remain stable; do not continuously retry an unstable system.
3. Accepted rows must be restricted to independently established trusted OS/service roles plus the exact owned operator/sudo ancestry and the current exact selected service generations. SSV/code-signing/protected ancestry can support a frozen Apple daemon identity, but an Apple signature/path alone does not prove a generic utility is a daemon or establish its invocation provenance. Third-party roles require separately verified existing launch/service authority and protected executable/loader/input closure; no arbitrary root baseline list and no broad `/usr/local` or `launchd`-child exception. At phases where the known group is quiescent, its old PIDs are not exceptions: their actual exits must already be proven. At restoration use only the newly bound current generation. A transient owned command is permitted only within its exact recorded parent/process birth chain and lifetime.
4. Any root process not classifiable under those fixed roles fails closed, including detached native children, renamed interpreter images and old operator instances. Do not kill it, read arguments/environment or automatically authorize a new exception. The later before-isolation and after-restoration censuses are necessary current proof, but cannot retroactively make an earlier unknown phase safe. Retain the exact records and failed/unknown operation disposition.
5. Reuse kernel process identity/ExitWatch concepts from transaction/process.rs, extending only the private finite handover reader as needed. The login ps parser is useful for ordinary diagnostic formatting, but its second-resolution `lstart`/`comm` and intended narrow UID612 check are not sufficient as the final root-writer proof. No generic process supervisor, command execution interface or root process killing is needed.

Required negative fixtures are: detached native child with interpreter gone; known interpreter execs different executable without changing PID; replaced birth/PID; same executable but unowned PID; unrelated root helper; a vanished parent row with an unseen possible child; truncated/inaccessible census; old service PID after the quiescent phase; unknown third-party role; and root bridge reopened between the pre-census and final fence. Positive fixtures must bind legitimate OS roles and exact fresh service/operator generations without accepting broad path classes.

## Honest assurance and Owner tradeoff

The accepted Spec explicitly excludes impossible-to-revoke copies used by an omnipotent Owner. It does **not** automatically classify a root process reached from a nonroot-accessible vulnerable bridge as trusted Owner activity. A handover census may establish no currently unclassified in-flight writer under the existing trusted-host/OS assumption and a complete frozen role classification. It cannot prove the host never ran arbitrary root code, that no prior persistence/injection exists, or that process metadata authenticates historical provenance.

Recommendation: prepare the finite ingress-first, fail-closed handover using the accepted trusted-host assumption, and make its exact scope and classification visible in the one Owner package. If a current non-OS row remains unprovable, disclose the exact row/role and required resolution once; do not silently expand trust. A controlled reboot **after ingress is persistently retired** can remove inherited live processes at the cost of interrupting all host tasks; it is separately authorized and changes the operation plan. Reboot alone is not proof against previously installed persistence or a writable startup closure. If that stronger historical-compromise assurance is required, it needs separate host remediation/attestation and cannot honestly be manufactured by this deployment Goal's metadata census. No automatic reboot or broad process shutdown is recommended or authorized here.
