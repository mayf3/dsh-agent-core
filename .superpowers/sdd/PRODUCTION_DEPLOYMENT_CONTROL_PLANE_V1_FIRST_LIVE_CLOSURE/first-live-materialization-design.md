## Evidence, choice and non-goals

The completed disabled installation holds six real role keys, an immutable initial registry and disabled profile. `Registry::enroll` and custody signing are existing crate-private primitives; no post-genesis root operation exposes the required composition. Native adoption implementation consumes signed AdoptionGrant/StandingActivationGrant/ObservationPolicy, protected configuration/enrollment/issuer bindings and a FirstLiveMaterializationReceipt. Creating JSON or an Agent-authored PASS does not satisfy those interfaces.

Use one package-bound native materializer for this exact dsh operation. Reusing the genesis runner would misrepresent a completed old attempt and its now-expired grant. A generic signing/enrollment RPC unnecessarily expands the trusted surface. The selected helper has no socket endpoint, command executor, key generation, credential operation or arbitrary signing domain. Root installation and invocation remain covered only by the next explicit Owner operation grant. It never signs Builder, Reviewer, Verifier or Recovery attestations. Its direct signatures use only Authority domains; existing Registry::enroll additionally emits only the ordinary authenticated Pending DeploymentRegistryLedger and ProducerSnapshot through local-deployment-registry. No READY, GoalReceipt, closure, build, review or recovery proof is synthesized. Genuine existing issuer preparation and fixed observer retain those roles.
