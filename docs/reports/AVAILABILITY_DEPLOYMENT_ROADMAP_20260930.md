# 可用性优先的部署重构与存量上线方案

日期：2026-09-30。基线：`mayf3/dsh-agent-core@51f477394fbab0234eae807bacd0f942ffdc22ed`。

**性质：供执行者采用的设计建议和交接，不是 accepted Spec、生产授权或能力完成回执。** 本 PR 不修改现有架构、合同、治理入口、运行代码或生产状态。涉及新持久协议、服务拆分、权限或失败语义的步骤，实施前按现有规则完成对应的有限决定；普通复用工作不等待整个路线图成为新平台。

配套：[逐步实施计划](../superpowers/plans/2026-09-30-availability-and-backlog-rollout.md) · [部署 backlog 与上线波次](DEPLOYMENT_BACKLOG_ROLLOUT_20260930.md)。

## 1. 用户结果与证据边界

目标是同一个 HR、同一个入口能持续使用；任务可取消、可恢复；部署失败不拖垮其他 Agent；普通发布不临时索取全量 root。用户已报告 HR 经新 turn、worker、模型回复和正常结算恢复，这只能作为**用户提供的恢复报告**，不是本 PR 重新验证的生产状态。

本轮只通过 GitHub、历史交接和用户提供材料进行整理，没有访问远程桌面或操作本机。可确认源码 main 包含 [#369](https://github.com/mayf3/dsh-agent-core/pull/369)；现网临时补丁、配置、服务身份、启用状态和全 fleet 验收尚待 T0 取得范围受限的实际记录。不能拿 main SHA 或 `/health=200` 代替这些事实。

### 建议验收目标，而非已经兑现的保证

| 指标 | 初始目标与适用条件 |
|---|---|
| 用户可用性 | 滚动 30 天 99%；分别记录持续业务探测与实际请求成功率，不用接收 ACK 代替完成。低流量无样本不能算 100%。 |
| 单任务恢复 | 主机、存储、模型依赖正常且没有不可隔离外部写入时，60 秒内恢复同一 Agent 的新任务执行能力。 |
| 发布回退 | 旧版兼容、主机和磁盘正常时，已确认失败的普通发布 3 分钟内恢复上一可用版本。 |
| 已收任务 | 确认收到前持久化；进程崩溃不丢已确认任务，不盲重发结果未知的外部动作。 |
| 范围 | 单 Agent 的故障不自动扩大为全 fleet 停工；控制面故障暂停新变更而非撤销已运行服务。 |

99% 的 30 天全天时间预算是 7 小时 12 分钟，不代表单次故障允许拖这么久。治理等待、错误 fence、内部资格检查导致的不可用计入指标。外部模型/网络/飞书故障单独归因，也保留用户侧总指标。以上时间是拟议验收阈值，不是开发工期承诺。

单机方案不覆盖 Mac 睡眠、断电、磁盘毁损和整机网络中断；不得宣称真正多机高可用。独立备份和恢复演练需要做，备用常开主机属于后续独立范围，不作为此次 backlog 上线前置。

## 2. 复用已有机制，不重新造部署系统

当前 [PDC V1](../specs/PRODUCTION_DEPLOYMENT_CONTROL_PLANE_V1.md) 已描述：不可变制品、完整依赖、统一事务锁、阶段回读、回退、常规发布长期授权、初始化与日常发布分离。它是设计/实现依据，**不表示每个动作已经安装并可调用**。

| 保留或复用 | 实际要补的缺口 |
|---|---|
| 现有 DS/shim 的受控发布、回退、注册单元 | 证明相同入口可以连续发布两个版本并回退；不要因版本哈希变化改一次执行器源码。 |
| `scripts/lib/deployment-reuse/receipt.py` 与已有测试 | 精确操作查询可移植化；不使用 `STATUS.last_receipt` 猜本次结果。 |
| 现有 Router、store、身份与 Broker | 完整任务取消/重置、正确的服务身份与权限验证；不新建 Session 业务权威。 |
| `svc-workflow`、Forum outbox、执行记录与查询 | Workflow 是业务状态权威，Forum 是协作/投影，执行记录是证据；不另建一个全能状态后台。 |
| 已有 controller 与 GitHub command bus | 提交、接收、运行、结果分开；重复任务去重；不另建“监督监督者”的服务。 |

[#360](https://github.com/mayf3/dsh-agent-core/pull/360) 是尚未交付的两阶段维护方案。按需复用其分析，不能把它或完整新 `agent-deployd` 变成普通发布、只读功能的普遍前置。当前可用的受控执行器先满足已登记服务的最小闭环，再逐步迁移。

## 3. 目标结构与迁移顺序

```text
现有用户入口 → 稳定接入/结果投递 → 一个正式 Runtime → 每 Agent worker
                                      ↘ 受控工具执行边界
独立候选 Runtime → 测试身份、测试状态、无正式投递/调度权限
固定部署执行器 → 受审版本安装、事务查询、切换、验证、回退
```

先交付“完整制品 + 有界切换/回退”，再拆稳定接入层。第一阶段允许如实记录短暂切换中断，不宣称零停机。候选 Runtime 不能连接正式 Scheduler、消费正式飞书队列或使用正式工具写入凭据。两个正式调度者不可并存，磁盘上保留两套版本不等于双主执行。

## 4. 发布单元

一个发布单元绑定：源码仓库与 SHA、构建配方、架构/工具链、完整应用树、Node/harness/依赖摘要、非秘密配置版本、状态格式兼容范围、既有部署 profile、当前目标代次、回退目标、所覆盖的 Goal 与验证证据。

代码、运行时依赖、配置引用、业务状态分离。不可变版本可共享内容寻址的 Node/harness，但不能把旧版的运行时目录“搬走复用”。禁止覆写整个 authsvc home；禁止把生产状态或秘密打进发布包。

正式激活的制品必须与测试的制品相同。manifest 不接收任意 shell、外部路径或权限；如需当前版本指针，由受控执行器解析/维护，不能给候选包引入任意符号链接权限。现有固定目标目录也可继续采用，前提是切换和回退已验证，不为目录布局单独重建平台。

现场热修先做只读差异清单，复原到源码分支并验证。未知差异只阻止**可能覆盖它的发布**，不阻止独立 UI、文档采用、离线测试等工作。不能以“源分支更新”推断包含现网有效补丁。

## 5. 普通发布流程

1. 构建完整制品；缺模块、依赖、配置或不兼容状态格式，在候选侧失败。
2. 在独立环境、等价服务身份下启动候选；实际执行普通 Agent/HR 恢复相关路径；测试身份与业务身份隔离。
3. 进入既有部署事务：核对目标、当前代次、权限范围与回退；在锁内做权威 preflight。
4. 有界停止领取新工作；已在途工作按既有生命周期处理。排队不等于完成，不以“PID 不见了”代替外部动作判定。
5. 切换一次，验证加载版本、配置和服务账户可读写；进行已授权的低风险业务验证。
6. 成功才提交正式回执；已确认失败按既定回退路径收尾。响应丢失查询同一 operation，不换 ID 盲重发。

所有修改同一主机已登记生产目标的入口共用现有全事务锁，覆盖切换、启动、验证和回退。排队、构建、等待人为验收不占生产锁。第一阶段不削弱 PDC V1 的全主机互斥为未经验证的细粒度锁。

操作结果未知时，暂停相关新变更并作有界回读；不要因本控制面不可用而停止已确认正常的业务。回退只恢复该事务拥有的代码/配置和服务状态，**不回退升级期间新产生的业务数据**。

## 6. 授权过期与部署器故障

拟议目标：新变更须有当时有效的授权；一笔已接纳事务的查询、取消候选、回退与安全收尾，在接纳时由固定 profile 预授权。授权后续到期不允许开新事务，但不把既有服务困在中间状态。

这改变授权/恢复语义，须在实际实施该步骤时补齐对应决定和回归；不能自行延长过期 grant，也不能以本路线图推导生产授权。部署器自身升级有独立回退入口，不允许“先装新 reader，再让新 reader 证明自己的安装”。

## 7. 资格测试不能封锁业务

专用测试身份、generation、状态库和工具权限；不再借效率管家等用户 Agent 作为私有资格子进程。候选测试失败停止候选，不设置 fleet-wide 永久维修模式。

正式运行默认没有测试资格绑定；显式有效的私有绑定才进入测试路径。对 `undefined/null/缺字段/错 agent/重启/混装版本` 做回归，不能单凭错误字符串推断有 root 窗口。是否确有持久资格状态，以生产者、消费者及实际差异证据说明。

资格流程超时须有已授权的确定性收尾，不能只续挂监视器；检查的是候选或部署事务，不得因此重新接纳未隔离的旧工具动作。

## 8. 重置作为完整产品能力

保留 `(agentId, sessionId)` 和原用户入口。一次重置的原始范围固定，原子或可恢复地更新：队列占用、声明、会话占用、关联索引、审计。重试旧 ID 不吸收后来任务；完成声明不能占满终身恢复次数，保留必要去重信息。

旧业务 UNKNOWN、进程存活、会话忙、新任务准入是不同维度。排队未执行可按真实队列移除结算；已知进程走受控停止/排空；外部操作结果不明保留 UNKNOWN 并限制实际冲突，不能伪造退出或靠删账本放行。D6 应急风险接受不自动成为今后每次失败的默认动作。

优先通过已有 store API 补完整闭环。事务存储迁移在功能稳定后实施：候选优先考虑单机 SQLite，复用已稳定的 PostgreSQL 也可；不得因此迁移无关业务。用 expand/contract 和新旧读写兼容测试，代码回退不依赖撤回业务记录。此项需要对应持久格式决定，**不阻塞已有 backlog 的安全只读上线**。

## 9. 身份、配置与维修入口

编码 Agent 不直接写生产 JSON、数据库、sudoers 或签名材料。固定执行器只接收已登记动作和受检参数；正常认证走服务签发，不手工用私钥伪造“正常 token 路径已通”。

所有健康/状态/读写检查至少有一次由实际服务账户完成，并验证文件 owner/group/mode、目录访问和原子写回。root 能读取不等于服务能读取。localhost 诊断使用不经代理的明确 transport；代理错误不能直接归因为 OAuth client 配置坏了。

仅按本次实际修改范围核对遗留 scopes、文件权限和应急全量 sudo；有受限恢复入口且经验证后再回收全量权限。凭据是否暴露要按实际日志证据判定，不能盲目轮换全系统。

## 10. backlog 不等整套重构完成

发布波次与重构任务是两条关联但不互相全量等待的序列：

```text
T0 稳定版/现有覆盖核对
  → 已安装且满足要求：VERIFY_ONLY，不重装
  → 缺代码的同一目标：补缺并走已有可用 DS
  → 缺权限/启用条件：只保持该能力 dormant
  → 独立低风险能力：先发布并验收
```

首先完成候选制品/回退的最小可用路径，不要求 SQLite、独立接入层、完整两阶段维护、全局治理采用全部完成才上一个读面。每个实际发布单元可覆盖多个已兼容 Goal，但逐 Goal 记录业务结果；代码安装次数按制品统计，不按 PR 数量重复重启。

## 11. 分工与防反复

一个集成责任人汇总现有 Goal；实现者可在不冲突分支并行；生产事务只有一个实际执行者。用户将自行指派执行 Agent，本 PR 不创建控制任务或后台监视器。

首轮复核只针对实际变化；后续看差异和被失效的证据。评审必须指出可达错误，未来泛化与偏好进入后续任务。发现没有有效改动可以正常结束。预算按原 Goal/intent 累积，换标题不能清零；无新输入的重复检查要去重，但真实新故障不能被固定轮数压掉。

现有 [#364](https://github.com/mayf3/dsh-agent-core/pull/364) 承载中央治理 #21 的本地采用；继续它，不新增同类规则 PR。该采用与生产改造分离，不能让文档复核占住生产窗口。

## 12. 设计到验收的对应表

| 交付 | 证明，不是叙述 |
|---|---|
| 完整制品 | 干净目录重建；故意移除依赖会在激活前失败；旧版不受影响 |
| 可恢复发布 | B→C→B；断连查询同事务；执行器重启后收尾；加载版本/服务账户/真实请求都正确 |
| 局部重置 | 同一 HR 在取消、超时、worker/controller 崩溃后可继续；未授权零修改；另一 Agent 仍能完成 |
| 隔离资格 | 候选卡住、grant 到期、controller 离线时，原业务请求仍能完成 |
| 数据一致性 | 中途故障不出现仅标记无审计、失配索引、错误权限；旧版可读取升级后的兼容状态 |
| 稳定入口 | 持久 ACK 后崩溃不丢任务；切换短暂排队可见；无双消费/双调度 |
| backlog 消减 | 对已包含 Goal 只补现场验证；关闭一项必须有独立业务证据，不用 PR 合并替代 |
