## Implementation and wire

`POST /v1/conversation/history` and `/events` remain behind existing per-request online Basic verification and explicit `history`/`events` operation grants. Old `[resolve,send,result]` configuration does not gain these operations. Every row/event rechecks subject, communication scope and current target/Binding; handles/cursors do not confer access.

History accepts exactly `{session_handle,direction:'older'|'newer',cursor?,limit?}` (default 50, max 200), or exactly `{content_cursor}`. It lists only registered own requests and their visible exact replies. Projection IDs use `request_owned_projection_v1` (`msg_nc1_*`), separately from native IDs. Missing native IDs/times are null with availability. Assistant time is source `reply_created_at`; derived `reply_to` is `native_turn`, while absent native parent stays null. Attachment binaries, full-main/fresh/archive remain unsupported.

The existing atomic document carries immutable message appearance positions independent of the bounded event ring. User positions are assigned when session coordinates first become durably discoverable, including lost-receipt recovery; assistant positions only when a settled result is committed. Pending replies consume no future reply position. No `submitted_at` ordering or array offsets cross snapshots. `next_cursor` continues the same direction/query/limit and frozen upper boundary; on the last newer page it becomes a reusable incremental cursor. `after_cursor` starts newer reading after that snapshot (same limit), including from an older page. Drain the snapshot before advancing to after_cursor if all old messages are needed. Empty increments preserve progress. Cursor source/epoch/generation/query mismatches fail explicitly.

Response serialization is capped at 1MiB, shortening a list page with `truncated/has_more` and a legal continuation. Each body page is at most 6144 UTF-8 bytes; cursors bind scope, request/part, generation, content version/retention and a valid UTF-8 boundary. `body_sha256` hashes the complete redacted projection (`body_hash_scope=complete_projected_text`); `body_page_sha256` hashes the actual returned page. Redaction is explicit. Both user and assistant body cursors expire; unfinished user text is bounded by submitted_at + original retention, and user visibility uses the earlier of this bound and result expiry. Tombstones/UNKNOWN remain, with expired/not_projected bodies explicit. Existing v1 records have no user text; no logs are consulted to backfill it.

Events are atomically written with canonical state/ref under the existing store lock; stable IDs and store-monotonic seq are also monotonic within each scope. Native association is copied from the same durable row. Unknown source occurred_at stays null with availability; persisted_at is separate. Callback retries cannot mint a second reply event. Events default 50/max 100; cursors bind scope/request-filter/limit query and always resume at consumed high water. `has_more` uses the filtered set. Current target revocation removes old events, and explicit invisible requests fail without content. The 5000-event ring records actual per-scope dropped-through watermarks; expired cursors return EVENT_CURSOR_EXPIRED with scoped retained coverage. Scope coverage never substitutes the global high water for visible records. Original get_message_result remains canonical; pull discovery is not active notification or a latency promise.

History/events call only the nonmutating snapshot reader after auth; they do not construct/migrate/recover the store or call native source/execution/monitor/send/Workflow paths. Existing service startup, send and reconciliation remain the only projection writers.

## Migration and stop/rollback

v1→v2 happens under the existing writer lock and one atomic replacement. It preserves request identity/digest, native coordinates, status, UNKNOWN and tombstones. Existing result bodies remain readable; missing user text and pre-migration events stay not_projected. Existing records receive positions at projection adoption, without fabricated historical event times. A direct read of an unmigrated v1 document does not write it; deterministic legacy snapshot cursors fail CURSOR_STALE across migration/change instead of silently moving to a different source.

v1 code rejects v2 documents as RESULT_STORE_INVALID. Do not downgrade a live v2 store or restore an earlier snapshot over newer reservations. If future authorized operation needs to stop sends while preserving retrieval: remove only DSH `send`, retain separately authorized `result/history/events`, keep the MCP adapter enabled and all durable/source records. Full adapter disable blocks reads too. Any future migration backup, activation, configuration change or rollback belongs to its original runtime Owner under a separate mandate; none ran here.
