# Same-attempt disabled genesis reconciliation procedure

This procedure is a prospective controlled-operation attachment to the corrected
package request. It grants no permission. It reuses accepted Spec CTR-DCP-017 and
section7; it does not amend a Product Contract or authorize activation.

The preceding exact package was executed once and stopped in read-only sudoers
preflight. Actual evidence is recorded in
[the attempt report](PRODUCTION_DEPLOYMENT_CONTROL_PLANE_V1_GENESIS_ATTEMPT_20260918.md).
The original Owner grant remains attributable only to the old exact package.
A new exact-package authorization is required before replacing any installed byte
or invoking the corrected privileged runner. Keep the original attempt ID:
`genesis-65559dd-20260918-01`.

## Bounded difference from the first operation

The corrected binary reads safe root-owned OS-compressed sudoers files only for
read-only census. It does not alter flags or contents of system configuration and
does not relax artifact, authorization, executable or private-key validation.
There is no new controller API, root command interface, generic resume switch,
new service target, new numeric identity or business Goal enrollment.

The only additional privileged effect requested is replacement of the already
installed old bootstrap runner with its exact independently reviewed correction.
All remaining install/login effects are the previously reviewed disabled-genesis
sequence. The original grant, lock and evidence are retained. No rollback erases
or replaces the original lock or journal root.

to obtain protected metadata/bytes as nonsecret evidence. Operator parsing and
comparison runs as the ordinary caller. Never execute a caller-owned root helper.
A single failed comparison stops before the runner replacement:

1. Reverify the new inert package's six external pins, exact source, independent
   review, binaries, support schema, policy, registry, host and numeric identities.
   The companion `reconciliation-plan.json` binds both old and new pins, prefix,
   runbook digest, retained evidence and the original attempt ID.
2. Code directory must remain root:wheel0755 and contain **only**
   `agent-deploy-bootstrap`. Its old SHA256 must be
   `2a8550ac3ffde4ccd21d501d7869608628bacd8ccb4feaab44aeb1803546d301`, root:wheel0555,
   one link, flags0, and no ACL. Strict protected ancestors remain required.
3. Original protected grant must remain root:wheel0600, one link, flags0 with
   SHA256 `dc416250cf805465ab50de917ac1f59323a6096b2f0745600d40a374ded3a37e`.
   Read its nonsecret JSON and match the original six pins, host and attempt.
   Its expiry does not authorize a new action; it is historical preimage evidence.
4. Journal root must remain root:wheel0700 and contain **only** `bootstrap.lock`.
   The lock must remain root:wheel0600, one link, flags0, empty, with creation-era

   attempt subdirectory must still be absent. No active bootstrap/login process or

5. All native-step targets remain absent: deployment state/custody/registry,
   reviewer HOME/workspace, controller plist, socket parent, new authorization
   destination and original attempt directory. Check both existence and symlink
   presence. `_dcp_review`/UID612/GID612 and `_agentdeploy`/GID602 remain absent in

6. Retained system-service observations and old operation receipts must be readable.
   Existing system plists/sudoers are never changed by reconciliation. Fresh complete
   protected content census still occurs in the corrected native installer before
   any InstallStep. Any incomplete census or unrelated drift stops there.

This gate reconciles an observed preflight-only prefix. It does not grant an
exception for an unpaired InstallStep intent, uncertain key creation or an existing
native installation. Such a finding returns to explicit reconciliation, never a
new attempt ID or blanket continuation.

## Exact execution after separate Owner authorization

Create one fresh external `GenesisOwnerGrant` root:wheel0600, at most3600seconds,
with the new six pins and the **same** original attempt ID/host/Owner. Use a new
protected authorization filename specified by the companion plan; never overwrite
the original grant. The original package directory remains immutable.

Use the pinned Apple `/usr/bin/install` to replace only the known old protected
runner with the exact corrected packaged runner, mode0555/root:wheel. Hash the
installed result as the ordinary caller and compare its external reviewed digest
before any root invocation. An interrupted copy or mismatch stops immediately;
no partially copied executable runs.

Then call only the fixed installed path with `install`, the corrected package,
new grant and six literal external pins in PLAN/PACKAGE/SOURCE/REVIEW/REGISTRY/POLICY
order. The native runner rechecks authorization, host, its installed hash, package,
permanent mutex, prefix/identity census, protected existing surfaces and then writes
the original attempt journal before its first InstallStep. Do not rerun on error.

Only after `INSTALLED_DISABLED_PENDING_OWNER_LOGIN`, invoke `reviewer-login` with
exactly the same new grant/pins. Owner handles the visible device login locally;
no caller credential is copied and no device code/private credential is captured
in evidence. Completion must produce protected login-result and auth metadata.

Export fixed protected public receipts, service/trust configuration, pending
registry entry, installed hashes, disabled plist/profile, key/credential metadata,
absent activation/socket markers, and existing-process metadata for independent
verification. Private key/auth file contents are never exported. If a local sudo
session expires, another local authentication may be needed for read-only exports;
it does not authorize additional effects. Keep the terminal available for readback
instead of appending `exit` to its invocation.

## Failure handling

- Before replacement: leave the old prefix intact; retain mismatch evidence.
- Replacement fails or installed hash mismatches: stop before native execution.
  Restore the exact original runner only if its own bytes/metadata and absence of
  every native-step effect are independently established under this newly accepted
  bounded recovery authorization. Never guess the destination state.
- Native installation fails: preserve original attempt, lock, intent/results and
  all partial effects. No retry or fresh attempt. The reviewed `rollback` may remove
  only exact-hash nonsecret files recorded in completed steps. It retains keys,
  identities, state, runner and journal; unpaired effects require reconciliation.
- Login fails/times out: retain login-intent as unknown and do not retry. Service
  remains disabled; no credential value is read to diagnose it.

No branch here enables/starts a service, changes sudoers, restarts existing tasks,
installs a target runtime, retires old entrances, switches routing or performs a
real deployment. Parent Goal remains incomplete after successful disabled install.
Subsequent activation/retirement/canary/standing Train/joint-release proof remain
separately prepared and authorized under the parent Goal.
