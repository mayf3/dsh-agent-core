# Original executor qualification-only private startup

## Decision and boundary

This proposal resolves only the same-final-binary qualification/startup cycle.
QE-C01 remains unchanged. The original independently authorized deployment/proof
procedure creates the forward prerequisite; the HR recovery operation consumes
it later. The procedure is owned by the same separate original Deployment Agent
(thread:01a0ad06-249f-7632-809b-961b93c3b113), authenticated through its sealed
fixed root execution entry and actual kernel namespace/FD custody. A thread
label, euid, supplied JSON/PASS or source snapshot is never authentication.

The original procedure is pinned by OWNER_RUNBOOK.md SHA256
d8cfc5a3925c29ee843258a8077f57f4d8223f44bf697bbd24edba011753911e,
§① trusted deployment and §② completed post-deploy proof. Old2097/7c command
literals are not authority to replace the final consuming closure. The final
whole-app identity remains the exact consuming binary identity; neither a
Router-only digest nor an earlier/pre-promotion different binary substitutes.

This is a proposed bounded nonproduction phase clarification, not permission to
perform deployment, reads, restarts, messages or recovery. A future real package
must separately bind actual execution authority/current preimage/rollback,
installed routes, exact entry/closure and unused phase operation identities.

## Contracts

**QF-C01 — Distinct causal phases.** The separate original qualification driver
owns trusted deployment and actual original proof procedure for the exact final
whole-app closure, including both controlled restarts and legitimate completed
same-Agent turns. Only that completed OWN-event sequence may seal the existing
floor4/validator3 receipts under QE-C01. Its installation of the new-kind
validator precedes every HR new-kind producer. The subsequent R2/MI operation
still checks those actual receipts before its own stop/restart, promotion and
producer. No HR action proves its own prerequisite, moves that precheck, mints
initial PROVEN, or reuses its startup to perform qualification.

**QF-C02 — Fixed private qualification context.** The original executor's sealed
fixed driver may own the finite qualification startups needed by its original
procedure on the same final whole-app closure. The driver itself performs and
observes those callsites. At the gated entry, a distinct qualification-only
private context authenticates the original admitted root entry/package and its
genuinely held namespace/OFD custody before Router import. It binds the same
immutable whole-app/validator identity, actual owned child, original procedure
identity and exact startup phase. Missing, unbound, wrong or lost capability
rejects before Router import; no caller-selected context/action/path, public
DS/bootstrap request, environment flag, UID/thread check alone or credential
change may install it. Ordinary/manual startup remains rejected. The context is
finite, private and phase-bound, never an ordinary post-window mode.

**QF-C03 — Qualification does not consume HR recovery.** This branch neither
loads/consumes an HR quiescence bundle nor settles the s256 record; it cannot
create HR launch authorization, consume the fixed HR one-use operation ID,
clear/recreate a fence, alter old business outcome or replay an execution.
Existing durable validator/floor handling and recovery fences remain active.
Fresh proof turns come only from legitimate attributable Owner delivery and
actual native/Broker completion, never driver impersonation, automatic sending,
health-only acceptance or old-turn replay. Other existing Router responsibilities
remain unchanged; qualification startup is not HR business-admission proof.

**QF-C04 — Owned sequence and receipt boundary.** Keep actual original custody,
closed source/entry qualifications and continuous whole-app identity across
trusted deployment, both proof restarts, store/generation observations and actual
turn completion. Original procedure success requires every QE-C01 predicate.
The existing sealed floor4/validator3 receipts are emitted only after real
completion with actual observed times; no new protected output, public API,
receipt field/vocabulary or actor is introduced. No source byte match, retained
snapshot, constructed timestamp or isolated boot substitutes for OWN-events.

**QF-C05 — UNKNOWN and final handoff.** Missing/ambiguous/changed events,
uncertain ordering, changed binary, lost private custody, incomplete startup or
turn completion is sticky UNKNOWN with no seal and no blind retry/replay.
Preserve actual known child/state and safe custody; timeout is not release
permission. A completed qualification phase closes only through the original
reviewed owned disposition, without authorizing an extra uncontrolled startup.
Only after qualification and separately bound R2/MI preconditions may the
unchanged HR private one-use startup/settlement/readback run. Qualification PASS
alone is not H2–H6, installed-profile, business-recovery or production readiness.
